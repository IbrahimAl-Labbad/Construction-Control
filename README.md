# Construction Control — طبقة التحكم الإداري

نظام رقابة وإشراف إداري ومالي لشركات المقاولات والإنشاءات.

---

## 1. نبذة عن النظام (Overview)

طبقة التحكم الإداري (Management Control Layer) ليست نظام ERP شامل وليست منصة محاسبية متكاملة، بل هي **طبقة رقابية عليا** تلتقط الإشارات التشغيلية والمالية اليومية وتحولها إلى:
- **شفافية للإدارة العليا** (Executive Visibility)
- **سلاسل مسؤولية واعتماد واضحة** (Accountability Chains)
- **مسارات موافقة منظمة** (Approval Workflows)
- **كشف الاستثناءات والتجاوزات** (Exception Surfaces)
- **تقارير دورية للإدارة** (Executive Reporting)

المدير هو **المستفيد والمستهلك الأساسي للمعلومة**، بينما يمثل المهندسون الميدانيون والمحاسبون ومسؤولو المشتريات **مصدراً لإدخال البيانات التشغيلية**.

---

## 2. الأدوار الأربعة المعتمدة (v1 Roles)

1. **المدير (Manager)**: صاحب سلطة الاعتماد النهائي لكافة المصروفات والعهد والمشتريات والمستخلصات ومستعرض التقارير التنفيذية.
2. **المهندس الميداني (Engineer)**: يرفع تقارير التقدم الميداني ومطالبات المصروفات التشغيلية وطلبات العهد.
3. **المحاسب (Accountant)**: يسجل المصروفات ويسوي العهد ويعد سجلات الفواتير والمستخلصات ويسجل مبالغ الرواتب.
4. **مسؤول المشتريات (Purchasing Officer)**: ينشئ طلبات الشراء ويدير علاقات الموردين وأوامر الشراء.

---

## 3. القواعد المعمارية الصارمة (Engineering Principles)

- **الواجهة عربية أولاً (RTL-First)**: استخدام CSS Logical Properties مثل `ms-*`، `ps-*`، وتجنب الخصائص الاتجاهية المطلقة.
- **الدقة المالية (Fixed-point Decimal)**: العملة المعتمدة هي الريال السعودي (SAR)، ويحظر استخدام أرقام النقطة العائمة (Float) في العمليات المالية، واستخدام `Decimal` من Prisma / دقة ثابتة حصراً.
- **سجلات مالية غير قابلة للتعديل (Append-only Ledger)**: لا تعديل على السجلات المالية بعد اعتمادها، والتصحيح يتم عبر قيود عكسية موثقة.
- **الحذف الآمن (Soft Deletes)**: لا حذف نهائي (Hard delete) للبيانات المالية؛ يتم استخدام `deletedAt`.
- **التحقق من المدخلات (Validation)**: التحقق الصارم في الخادم باستخدام Zod قبل الوصول إلى قاعدة البيانات.
- **الأمان والتحقق من الصلاحيات**: التحقق في جانب الخادم (Server-side RBAC) على كافة مسارات الخادم وإجراءاته.

## 4. البنية التقنية (Tech Stack)

- **الإطار**: Next.js (App Router) + React
- **اللغة**: TypeScript (Strict Mode)
- **قاعدة البيانات**: PostgreSQL + Prisma ORM
- **المصادقة**: NextAuth.js (Auth.js) v4 مع مزود بيانات الاعتماد والجلسات المخزنة
- **التصميم**: Tailwind CSS + shadcn/ui foundation
- **الاختبارات**: Vitest لاختبارات الوحدة + Playwright لاختبارات e2e

## 5. التشغيل والتطوير (Getting Started)

### المتطلبات الأساسية
- Node.js >= 20.0.0
- خادم PostgreSQL يعمل محلياً أو سحابياً

### الخطوات
1. نسخ ملف البيئة وضبط المتغيرات:
   ```bash
   cp .env.example .env
   ```
2. تثبيت الحزم:
   ```bash
   npm install
   ```
3. تهيئة قاعدة البيانات وإنشاء عميل Prisma:
   ```bash
   npm run db:generate
   npm run db:migrate
   ```
4. تشغيل خادم التطوير:
   ```bash
   npm run dev
   ```

### فحص الجودة والاختبارات
- فحص الأنواع (TypeScript): `npm run typecheck`
- فحص الأكواد (ESLint): `npm run lint`
- اختبارات الوحدة (Vitest): `npm run test`
- بناء الإنتاج: `npm run build`
